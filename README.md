# Duplex · 320 ms 音频与文本核对

只读展示当前 demo 的双轨 PCM、固定 320 ms 音频块、前置文本及 CUT。每个角色的公开文本直接读取导出结果，不在网页内重新分词、重排或补写。

## 当前展示

- 样本：`s04_6af1892f`，主题为“守望先锋源氏对安娜技巧”。
- 时长：386.24 秒；24 kHz；每块 7,680 个采样。
- 1,207 个物理音频块、1,208 条训练记录、14 个交互事件。
- 助手先说话：首条训练记录输入为空，目标为 `[0, 320] ms`；后续按下一块监督。
- 双角色文本前置，每块最多 4 个单位；汉字和英文单词各计一个，标点不计数。
- 末块含 3,840 个有效采样，每轨末尾补零 3,840 个采样。
- 虚线标记原始对齐 CUT，实线标记按最近 320 ms 边界取整后的实际停止位置；标记只画在被截断角色的音轨上。

音频和文本来自已完成排程、分块导出及续跑验证的现有 demo。这次仅更新展示，不调用 Writer、TTS、ASR 或强制对齐，不改变音频采样、增益及生成规则。

## 使用

点击任意块选中，再点击“播放此块”；也可播放本页或从所选位置连续播放。双轨模式为左声道 User、右声道 Assistant，也可分别独听。交互下拉框和事件标签用于跳转。

波形上方显示该块的前置文本。下方的对齐片段显示真实声学时间，二者应分开核对：无新文本的块仍可能有语音延续。展开 JSON 可查看所选物理音频块分别对应的 User 输入记录、Assistant 目标记录、控制标签和文本结束标记。

## 本地运行与发布

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

访问 `http://127.0.0.1:8765/`。无需 npm 或构建步骤。GitHub Pages 从 `main` 分支根目录发布，保留 `.nojekyll`。

## 文件

- `index.html`：分块波形、文本、试听和 JSON 检查界面。
- `assets/demo.json`：展示数据，包括真实音频块、导出文本、训练记录、对齐片段、事件和波形 min/max。去掉服务器绝对路径。
- `assets/user.pcm.deflate`、`assets/assistant.pcm.deflate`：原始 16-bit little-endian 单声道 PCM 的无损 deflate 压缩。点击播放时才加载并解压；浏览器使用同一个 AudioContext 时钟按采样区间播放。没有音量归一化、重采样或额外淡入淡出。
- `assets/demo-sans.woff`：Noto Sans CJK 字形子集，命名为 Duplex Chunk Sans；许可证见 `assets/OFL.txt`。
- `assets/demo.wav`：上一版页面保留的试听备份，不参与当前页面播放。

公开展示文件不包含 API 配置、模型、角色克隆参考录音、原始数据索引或服务器路径。原始场景来源为 OpenAssistant/oasst1（Apache-2.0），当前页显示 pipeline 生成的对话产物。
